# 長期記憶・RAG・世界線分離仕様書 (Memory Architecture & RAG)

本書は、泥濘 (Deinei) システムにおける長期記憶保持、忘却制御、親子リトリーバル（ChromaDB）、相対時間付与、世界線分離（Worldline Isolation）、およびKVキャッシュ最適化に関する技術仕様を定義したドキュメントです。

---

## 1. 概要

有限なコンテキストウィンドウ（16,384トークン）内で、破綻のない長期対話と推論速度（KVキャッシュ再利用率）を両立するため、泥濘は「16ブロック忘却スライディング」「親子リトリーバル（Parent-Child RAG）」「有向木世界線分離」を多層的に連携させています。

---

## 2. 記憶システムの基本構成

```
[ 会話入力 / 応答 ]
        │
        ├── 直近10件: 生ログ（直近文脈保持）
        ├── 未要約30件 または 7,000トークン超過: 要約圧縮（直近10件を残し約300〜500トークンへ）
        │        │
        │        ▼
        │   [ 16ブロック忘却スライディング ]
        │        ├── 最大16ブロック（約4,800〜7,000トークン）をコンテキストに循環保持
        │        └── 超過時は最古の2ブロックを押し出し
        │                 │
        │                 ▼
        │   [ 親子リトリーバル (ChromaDB) へ自動アーカイブ ]
        │        ├── 子データ: 重要キーワード・要約抜粋（検索インデックス）
        │        └── 親データ: エピソード全文（最大600文字/件）
        │
        ▼
[ 推論プロキシ (server.py) ]
        ├── 統合Top-6ランキング（Fact / Episode / 短期Web記憶を類似度順に厳選）
        ├── 相対時間タグ動的付与（[たった今], [3日前] 等）
        ├── アクティブパス（世界線）による記憶遮断フィルタ
        └── ユーザー発言直前への局所注入（Prefix Caching保護）
```

---

## 3. 各機構の詳細仕様

### 3.1 16ブロック忘却スライディング (Sliding Context Window)

- **要約トリガー**:
  - 未要約メッセージが30件蓄積されるか、または未要約トークン数が7,000トークンを超過したタイミングで自動要約が発火します。
  - 最新の10件は自然な文脈維持のため生ログのまま保持され、それ以前の蓄積ログ（約20件前後）が約300〜500トークンの要約ブロックへ自動圧縮されます。
- **循環スライディング**:
  - 要約ブロックは最大16ブロック（約4,800〜7,000トークン想定）を上限としてコンテキスト内に保持されます。
  - 16ブロックに到達した場合、最古の2ブロックがコンテキスト枠外へ押し出され、定常14〜15ブロックで循環維持されます。
  - 押し出された要約ブロックは破棄されず、長期記憶ベクトルDB（ChromaDB）へ自動的にアーカイブされます。

### 3.2 親子リトリーバル (Parent-Child RAG)

- **二層インデックス構造**:
  - 要約生成時に抽出された重要キーワード群を検索用インデックス（子）、要約ブロック全文（1件あたり最大600文字）を親データとしてChromaDBに二層保持します。
  - 検索精度の向上と、想起時の十分な文脈量の提供を両立します。
- **埋め込みモデルと検索閾値**:
  - 日本語埋め込みモデルとして `cl-nagoya/ruri-v3-310m` を採用しています。
  - Fact記憶（ユーザーの好み、設定、固有名詞）とEpisode記憶（過去の出来事・体験）を独立して検索（Dual-Query）します。
  - 検索距離閾値は、**Fact記憶が 0.135以下（コサイン類似度 0.865以上）**、**Episode記憶が 0.150以下（コサイン類似度 0.850以上）** に設定されており、高精度なマッチングのみを厳格に抽出して無関係なノイズを遮断します。
- **統合Top-6ランキングと動的注入制限**:
  - 想起されたFact記憶、Episode記憶、および過去5時間以内の短期Web記憶をプールし、コサイン類似度順にソートして**上位最大6件を厳選採用（Unified Top-6 Ranking）** します。
  - Episode記憶の想起文字数は、1件目を最大600文字にトリムし、2件目・3件目は類似度距離 0.130以下（類似度0.870以上）かつ累計1,100文字未満の場合にのみ追加採択され、**最大3件・合計約1,200文字（1,200文字到達で打ち切り）** を上限としてユーザー発言直前へ局所注入されます。

### 3.3 相対時間プロキシ (Relative Time Proxy)

- **ISOタイムスタンプと主観時間変換**:
  - ChromaDB内には不変のISO 8601タイムスタンプで記憶を保持します。
  - 推論時にプロキシ（`server.py`）側で現在時刻との差分秒数を動的に計算します。
  - `[たった今]`, `[15分前]`, `[3日前]`, `[2ヶ月前]` などの主観的な時間タグへ変換してプロンプトへ付与し、LLMの時間認識のズレを防ぎます。
- **Prefix Caching の保護**:
  - 動的日時情報はコンテキストの最後尾（ユーザー発言直前）へ注入するため、過去ログ領域のKVキャッシュ（Prefix Caching）を破壊せず高速応答を維持します。

### 3.4 世界線分離 (Worldline Isolation)

- **有向木分岐とスナップショット復元**:
  - 会話履歴を有向木（Tree）構造としてブラウザのIndexedDBに保持します。
  - 応答の再生成や過去発言の編集によって会話が分岐した際、メッセージノード単位で不変保持された要約スナップショット（`aiHistoryTextListSnapshot`）により、分岐当時の文脈・要約ブロック状態へ即時に復元されます。
- **アクティブパスによる記憶遮断 (ChromaDB)**:
  - 長期記憶リトリーバル時、ルートノードから現在ノードまでの祖先ノードID群（`active_message_ids`）を推論プロキシへ伝達します。
  - 他のブランチ（別世界線）で生じた事実やエピソード記憶はフィルタによって除外し、共通祖先の記憶のみを想起します。
- **要約・再構築時の一本化 (Consolidation / Linearization)**:
  - 30メッセージごとの要約圧縮時、過去の試行錯誤や分岐の枝葉を排し、現在のアクティブパスのみを1本の客観的あらすじ（要約ブロック）へ統合します。
  - 会話インポート時や記憶再構築（Rebuild Memory）時も、選択されたアクティブパスを線形化して整理された履歴として再インデックスします。

---

## 4. KVキャッシュ（Prefix Caching）の挙動と例外

通常の一連の継続的な対話において、泥濘はKVキャッシュ（Prefix Caching）を再利用し、プロンプト処理（Prompt Processing）を最小化します。
ただし、文脈構造が変更される以下のケースでは、キャッシュの再計算が発生します：

1. **自動要約発火時**: 未要約30件または7,000トークン到達時に直近10件を残して約20メッセージが新しい要約ブロックへ圧縮・置換されるため、Prefix構造が更新されます（次ターン以降は再びキャッシュが再利用されます）。
2. **Web検索発火時**: 検索ワード決定用の推論、および外部情報のコンテキスト注入により一時的な差分が発生します（推論速度を優先したい場合はWeb検索トグルをOFFに設定してください）。
3. **世界線（ブランチ）の切り替え・過去発言の編集時**: 会話ツリーの別ブランチや過去時点へロールバックした場合、その時点の文脈へキャッシュが切り替わります。
4. **記憶の再構築（Rebuild Memory）時**: 会話全体のあらすじ・記憶を一括再生成した場合。

---

## 5. データ保持とバックアップ

- **IndexedDB と ChromaDB の二重管理**:
  - 会話ツリーログ: ブラウザ内部（IndexedDB）に保持
  - 抽出された長期記憶（Fact/Episode）: PCローカル（`backend/data/chroma_db/`）に保持
- **ブラウザ履歴を削除した場合**:
  - 会話ツリーは消去されますが、ChromaDBの記憶は残ります。新しいセッションで対話を開始してもセッションIDが切り替わるため、別セッションの記憶と混ざることはありません。
- **ChromaDBが破損・初期化された場合**:
  - ブラウザ側に会話履歴が残っていれば、WebUIサイドバーの「記憶の再構築 (Rebuild Memory)」を実行することで、過去のログからFact/Episode記憶を一括再生成・復元できます。
- **バックアップ推奨手順**:
  - 定期的にWebUIメニューから「会話のエクスポート（JSON）」を保存し、あわせて `backend/data/chroma_db/` フォルダをバックアップすることを推奨します。
