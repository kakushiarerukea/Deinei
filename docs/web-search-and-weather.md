# スマートWeb検索・気象予報仕様書 (Web Search & Weather API)

本書は、泥濘 (Deinei) システムにおける自律Web検索パイプライン、地名逆引き（Nominatim）、リアルタイム気象データ連携（Open-Meteo）、およびKVキャッシュ保護に関する技術仕様を定義したドキュメントです。

---

## 1. 概要

泥濘は原則としてローカル環境内で動作しますが、ユーザーが明示的にWeb検索トグルをONにした場合に限り、外部APIから最新の時事情報や天気予報を取得して会話プロンプトへ動的注入するハイブリッド検索機能を備えています。

### 実演デモ動画 (自律気象検索・リアルタイム天気予報取得)

会話内でユーザーが天気を尋ねた際、Stage 1 の事前判定を経て外部気象APIから現在の天気・気温情報を自律取得し、プロンプトへ動的注入して音声読み上げ（TTS）とともに応答する実演です。

## 2. 正規表現ゲート ＆ 2段階自律検索パイプライン

```
[ ユーザー発言 ]
       │ (Web検索トグルが ON の場合のみ)
       ▼
[ 事前判定: 正規表現ゲート (should_trigger_search) ]
       ├── 検索意図なし（挨拶・短文・日常会話等） ───▶ Stage 1 推論を行わずローカル即時応答
       │
       └── 検索意図の可能性あり（トリガー語・疑問形式・地名等）
                 │
                 ▼
[ Stage 1: ローカルLLM高速クエリ生成 ]
       ├── 思考プロセスOFF（enable_thinking: False）による低遅延判定
       ├── 直近文脈・添付画像（Vision）から指示語（「この人」「その映画」等）を固有名詞へ解決
       │
       ├── 検索不要（文脈上不要と判断） ───▶ 外部通信なしでローカル応答
       │
       └── 検索必要（クエリ出力）
                 │
                 ▼
[ Stage 2: 外部取得 ＆ インメモリキャッシュ ]
       ├── 気象・天気 ───▶ Nominatim (緯度経度解決) ──▶ Open-Meteo API
       └── 一般・時事 ───▶ DuckDuckGo News (最大5件) / Text 検索
                 │          (0件時は Wikipedia フォールバック)
                 ▼
       [ 1時間インメモリキャッシュ (_SEARCH_CACHE) 登録 ]
                 │
                 ▼
[ コンテキスト最後尾へ動的注入 (ユーザー発言直前) ]
       └── 過去ログの Prefix Caching を破壊せず推論実行
```

## 3. 各機能の詳細仕様

### 3.1 事前ゲート ＆ Stage 1: ローカルLLM判定
- **正規表現ゲート (`should_trigger_search`)**:
  - LLMを呼び出す前に、ユーザー発言のキーワードパターン（検索トリガー語、疑問・質問形式、地名・天気パターンなど）を高速に正規表現判定します。
  - 明らかに検索の不要な発言（「おはよう」「うん」「かわいいね」等）は、この段階でStage 1の推論処理自体をスキップし、不要な推論負荷と遅延を防止します。
- **低遅延判定 (Stage 1 LLM)**:
  - 思考プロセス（Reasoning / thinking）を無効化した高速判定用推論を実行します。
  - 会話の流れや画像認識（`mmproj`）の解析結果をもとに、外部検索を行うべきかどうかを自律判定し、検索クエリを生成します。
- **文脈解決**:
  - 「あのニュースどうなった？」「この作家の他の作品は？」といった曖昧な指示語を、直前ログから具体的な検索キーワードへと復元・整形します。
- **無駄な通信の遮断**:
  - 「こんにちは」「好きだよ」「今日の調子はどう？」などの日常会話では、Web検索トグルがONであっても外部通信は発火しません。

### 3.2 Stage 2: 外部検索 ＆ キャッシュ機構
- **検索プロトコル**:
  - 速報・ニュース性のある話題: DuckDuckGo News 検索（最大5件）を優先
  - 一般知識・用語解説: DuckDuckGo Text 検索を実行（DDGSでヒットしない場合は、既定で有効な Wikipedia 概要検索へフォールバック）
- **インメモリキャッシュ (`_SEARCH_CACHE`)**:
  - 取得した検索結果はメモリ内に1時間保持されます。
  - 同一セッション内で同じ話題が続いた場合、外部APIへの再リクエストを防止し、即時応答します。

### 3.3 気象データ連携 (Open-Meteo ＆ Nominatim)
- **ジオコーディング (Nominatim)**:
  - 発言に含まれる地名（例: 「東京」「大阪」「札幌」など）を抽出し、OpenStreetMap の Nominatim API により緯度・経度へ変換します。
- **気象予報取得 (Open-Meteo)**:
  - APIキー不要の Open-Meteo API へアクセスし、対象地点の当日・翌日・翌々日の天候（WMOコード）、最高/最低気温、降水確率を取得します。
- **情景描写プロンプト連携**:
  - 取得した気象データはシステムプロンプトの情景描写指示（`*雨の音を聞きながら*` など）と連動し、現実に即したロールプレイ対話を実現します。

## 4. ワンクリックトグル ＆ KVキャッシュ保護

- **UIトグルスイッチ**:
  - チャット入力欄下部の専用ボタン（`ChatFormActionSearchToggle`）により、1クリックでWeb検索のON/OFFを切り替えられます。
- **トグルOFF時の動作**:
  - トグルがOFFの場合、Stage 1の判定処理を含め、外部ネットワークへの通信は遮断されます。
- **KVキャッシュ（Prefix Caching）の保護**:
  - 検索結果テキストは、プロンプトの最後尾（ユーザー発言直前）へ局所注入されます。
  - 過去の会話履歴領域のトークン列を変更しないため、KVキャッシュの再利用率を維持し、推論処理の遅延を抑えます。
